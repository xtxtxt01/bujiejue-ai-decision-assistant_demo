# 竞品能力跟进方案

> 基于 Reflectly / Rosebud / Mindsera 竞品分析，整理可在当前 Demo 中落地的功能及技术实现路径。

---

## 1. AI 即时 Insight（重点跟进）

**参考产品：** Rosebud  
**优先级：** P0

### 产品形态

用户完成一次纠结对话后，系统在对话结束时（或用户主动触发）生成一个 Insight 卡片，内容包含：

- 本次核心矛盾（一句话）
- 提炼出的价值观信号（如"你反复提到稳定感，说明安全需求权重较高"）
- 担忧点归因（理性担忧 vs 情绪性担忧）
- 历史相似案例引用（如有）
- 一条可执行的行动建议

### 技术方案

对话结束时，将完整 messages 发给 LLM，用结构化 Prompt 提取 insight JSON：

```json
{
  "core_conflict": "...",
  "value_signals": ["...", "..."],
  "worry_type": "rational | emotional | mixed",
  "action_suggestion": "...",
  "similar_past_case": null
}
```

- 后端将 insight 存入 `cards` 表的 `insight` 字段（TEXT/JSON）
- 关闭卡片时触发 insight 生成，结果在卡片详情页展示
- `similar_past_case`：查询用户历史已关闭卡片，短期用关键词匹配降级，中期升级为 embedding 相似度

**预估工作量：** 2-3 天（Prompt 设计 + 后端字段 + 前端 insight 卡片组件）

## 2. 低门槛分步输入

**参考产品：** Reflectly  
**优先级：** P0

### 产品形态

新建纠结时，不直接给空白输入框，而是引导用户回答 3 个问题：

1. 这是什么类型的纠结？（工作 / 关系 / 消费 / 目标 / 其他）
2. 触发事件是什么？（一句话，附 placeholder 示例引导）
3. 最担心的后果是什么？（一句话）

3 步完成后自动生成纠结卡片，AI 首条消息基于这 3 个字段生成，更精准、更有代入感。

### 技术方案

- 前端：将 `NewDilemma` 页从单输入框改为 3 步 wizard，每步一屏，顶部带进度点
- 后端：`createCard` 接口新增字段 `trigger_event`、`feared_outcome`
- LLM system prompt 将三个字段注入，首条 AI 消息基于结构化输入生成
- 三个字段同时写入用户核心记忆，作为本次纠结的结构化快照

**预估工作量：** 1 天（前端 wizard 改造为主，后端接口微调）

## 3. 即时正反馈

**参考产品：** Reflectly / Rosebud  
**优先级：** P1

### 产品形态

每次 AI 回复末尾附带一个结构化小卡片：

- 本次对话进展标签（如"你已说清触发原因 ✓"）
- 当前倾向指示（如"目前你的表达倾向：留下 60% / 离开 40%"，仅选择类纠结显示）
- 下一步引导问题

### 技术方案

在 `sendMessage` 的 AI Prompt 中要求返回附加字段：

```json
{
  "assistant_message": "...",
  "progress_hint": {
    "label": "你已说清楚触发原因",
    "tendency": { "option_a": 60, "option_b": 40 },
    "next_question": "..."
  }
}
```

- tendency 仅在"选择类"纠结（工作/消费）显示，其他类型只显示 label + next_question
- 前端在聊天气泡下方渲染小卡片，tendency 用进度条可视化

**预估工作量：** 1 天（Prompt 改造 + 前端 progress hint 卡片组件）

## 4. 长期模式识别（重点跟进）

**参考产品：** Rosebud / Mindsera  
**优先级：** P1（阶段一）/ P3（阶段二）

### 产品形态

用户积累 3+ 张已关闭卡片后，系统能识别并展示：

- 反复出现的担忧类型（如"你过去3次纠结都出现了'怕适应期'这个担忧"）
- 决策倾向模式（如"消费类决策中你倾向保守，职业类倾向冒险"）
- 行动 vs 放弃模式（如"你拿到 offer 后有2次都在最后关头放弃了"）

新建纠结时，如果匹配到已知模式，系统在对话中主动引用历史案例。

### 技术方案

**阶段一（关键词匹配，短期可上线）：**

- 关闭卡片时，LLM 从对话中提取 `pattern_tags`（如 `["fear_adaptation", "career", "offer"]`）并存入卡片
- 新建纠结时，查询历史卡片的 pattern_tags，找出重叠标签 ≥ 2 的历史卡片
- 将匹配结果注入对话 system prompt："用户历史上有类似纠结，最终选择了XX，事后评价是XX"

**阶段二（向量相似度，中期）：**

- 对每张卡片的核心矛盾文本做 embedding（调用 embedding API）
- 存入 `card_embeddings` 表，或引入 Chroma / pgvector
- 新对话时 top-k 相似卡片检索，召回历史记录作为上下文

**预估工作量：** 阶段一 2 天；阶段二 4-5 天（需引入向量库）

## 5. 结构化框架库（收窄版）

**参考产品：** Mindsera（50+ 框架 → 我们做 5-8 个高频场景）  
**优先级：** P2

### 产品形态

新建纠结时提供可选的场景模板，覆盖 5 个高频决策类型：

1. 换工作 / 接 offer
2. 关系沟通（表白 / 分手 / 冲突）
3. 消费决策（大额购买）
4. 目标复盘（坚持还是放弃某个目标）
5. 人生阶段选择（考研 / 创业 / 出国）

每个模板有预设的引导问题序列，AI 按框架逐步引导，而非自由闲聊。

### 技术方案

- 后端维护 `frameworks` 表，字段：`id`、`name`、`prompt_template`、`guide_questions`（JSON 数组）
- `createCard` 时可选传入 `framework_id`
- 框架的 `guide_questions` 注入 system prompt，AI 按序引导
- 框架选择 UI 放在 NewDilemma wizard 第一步（选类型时同步选框架）

**预估工作量：** 2 天（框架内容设计 + Prompt 工程，代码改动较少）

## 6. 周期性总结

**参考产品：** Reflectly / Rosebud / Mindsera  
**优先级：** P3

### 产品形态

每月自动生成"决策复盘报告"：

- 本月新增纠结数、已关闭数
- 反复出现的担忧标签排行
- 价值观变化信号（"本月你更多提到'稳定感'"）
- AI 生成的一条个性化洞察（200字内）

入口：Home 页底部展示"查看本月复盘"卡片（当月有 ≥ 2 张关闭卡片时出现）。

### 技术方案

- 新增 `GET /api/report/monthly?uid=&year=&month=` 接口
- 后端聚合该月已关闭卡片的 `pattern_tags`、`insight` 字段
- 将聚合数据发给 LLM 生成总结文本
- 结果缓存到 `monthly_reports` 表（按 uid+month 存储，避免重复生成）
- 前端新增 Report 页，或在 Home 页以卡片形式展示 summary

**预估工作量：** 2 天（聚合逻辑 + LLM 调用 + 前端卡片）

## 7. 历史内容回顾 + 事后复盘

**参考产品：** 三者都有  
**优先级：** P1

### 产品形态

已关闭卡片的详情页增加：

- 当时的决定内容和 AI insight 摘要
- "事后复盘"入口：用户可以写一段事后评价（"现在回头看，这个决定怎么样了？"）
- 复盘内容存入程序记忆，下次相似决策时被引用

### 技术方案

- `cards` 表新增 `retrospective` 字段（TEXT）
- 新增 `PUT /api/cards/{card_id}/retrospective` 接口
- 复盘内容写入后，追加到用户的 episode memory，并标注 `source_card_id`
- 前端：关闭卡片详情页底部增加复盘输入框 + 保存按钮

**预估工作量：** 1 天（接口简单，前端 UI 改动少）

## 8. 隐私与可控记忆（必须跟进）

**参考产品：** Rosebud / Mindsera  
**优先级：** P1

### 产品形态

在现有 Memories 页基础上补充：

- 每条记忆显示"来源"（来自哪张卡片），点击可跳转
- 核心记忆支持手动编辑（已实现，需完善 UI）
- 新增"清除所有记忆"高危入口（需二次确认 + toast 反馈）
- 重要记忆标注 AI 提取标签，让用户理解这条记忆为何被记录

### 技术方案

- Episode memory 存储时增加 `source_card_id` 外键
- 前端 Memories 页每条记忆显示来源卡片标题
- 新增 `DELETE /api/memories/all?uid=` 接口，后端软删除（先标记 deleted，不立即物理删除）
- LLM 提取记忆时返回值带 `source_card_id`，后端落库时存储

**预估工作量：** 1 天（来源字段标注 + 前端展示 + 清除接口）

## 实现优先级总览

| 优先级 | 功能 | 预估工作量 | 核心价值 |
|--------|------|-----------|---------|
| P0 | 低门槛分步输入 | 1 天 | 降低使用门槛，改善第一印象 |
| P0 | AI 即时 Insight | 2-3 天 | 核心差异化，对话结束即可感受到价值 |
| P1 | 即时正反馈 | 1 天 | 增强单次使用价值感 |
| P1 | 隐私与可控记忆（来源标注） | 1 天 | 建立信任，必须跟进 |
| P1 | 历史内容回顾 + 事后复盘 | 1 天 | 让记录有长期价值，形成闭环 |
| P2 | 结构化框架库（5个场景） | 2 天 | 差异化能力，适合 Demo 展示 |
| P2 | 长期模式识别（阶段一，关键词） | 2 天 | 核心竞争力，关键词版可快速上线 |
| P3 | 周期性总结 | 2 天 | 依赖数据积累，先攒数据 |
| P3 | 长期模式识别（阶段二，向量） | 4-5 天 | Demo 阶段暂缓 |

**P0+P1 合计约 6-7 天工作量，完成后 Demo 体验会有显著提升。**
