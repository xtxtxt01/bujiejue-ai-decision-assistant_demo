## 一、模块定位

这是产品的**主流程模块**，也是核心价值所在。用户从创建一张纠结卡片开始，经历多轮个性化对话，最终做出决策并关闭卡片，沉淀为决策资产。

**一句话定位**：帮用户「看清自己是怎么做决定的」——不替你做决策，而是通过长期追踪你的纠结过程，发现你自己都没意识到的决策模式。

**与通用 AI 助手的本质区别**：核心差异不在于"有没有记忆"，而在于**记忆的用途和深度**，以及**围绕决策场景的专门结构化设计**（追问框架、纠结卡片、主动追踪、模式发现）——这些是通用助手不会主动替你做的。

---

## 二、产品结构

```
主页 = 纠结卡片列表
  ├─ 进行中的纠结（顶部，按最近更新排序）
  ├─ 已结束的（底部，可回顾）
  ├─ 系统偶尔贴"新发现"标签
  └─ 底部浮动按钮：+ 新纠结

点进单张卡片 = 该纠结的专属对话空间
  ├─ 顶部：纠结主题 + 核心矛盾 + 当前状态
  ├─ 中部：时间线式对话记录
  ├─ 底部：语音/文字输入框
  └─ 结束后：Insight 卡片（可折叠）

全局入口
  ├─ 我的洞察（Insight Gallery）
  └─ 我的记忆（记忆可视化）
```

## 2.1 纠结卡片创建（低门槛分步输入）

**参考产品**：Reflectly

新建纠结时不直接给空白输入框，而是引导用户分步输入，降低门槛、提升首条 AI 回复的精准度。

### 输入流程

1. **选纠结类型**：工作 / 关系 / 生活 / 财务 / 成长 / 学业（对应关注领域）
2. **触发事件**：一句话描述，附 placeholder 示例引导
3. **最担心的后果**：一句话

三个字段拼接为结构化输入，作为对话的第一条用户消息。AI 首条回复基于这三个字段生成，更有代入感。

### 卡片结构

系统通过对话追问（不超过 3 个问题）后，提炼出结构化卡片：

```
┌─────────────────────────────┐
│ 🔄 要不要换工作               │
│ 核心矛盾：成长空间 vs 稳定    │
│ 触发点：新领导来了，风格不适应 │
│ 不满点：工作内容重复          │
│ 状态：进行中                  │
└─────────────────────────────┘
```

字段：title、core_conflict、trigger_event、main_concern、status、dilemma_type、created_at。

**价值点**：卡片帮用户把模糊的焦虑转化为结构化问题——很多纠结在理清之后本身就减轻了。

## 2.2 个性化决策对话（多阶段对话引擎）

对话不是开放式闲聊，而是围绕单个纠结的**结构化追问**，分阶段推进。

### 对话阶段（Stage）

| 阶段 | 触发条件 | 系统行为 |
|------|---------|---------|
| clarifying（追问） | 前 3 轮且卡片无核心矛盾 | 澄清核心矛盾、触发点、担忧（≤3 问） |
| exploring（探索） | 信息逐渐补全中 | 深入挖掘，结合记忆给出针对性追问 |
| advising（建议） | 用户主动要建议 / 第 15 轮强制 / LLM 判断信息充分 | 综合多维度给出个性化决策参考 |
| closing（收尾） | 用户表达明确决定 / 卡片已关闭 | 确认决定、记录原因和残余担心 |

### 阶段判定逻辑

- 前 3 轮且无 core_conflict → clarifying
- 用户说出强决定关键词（"我决定"、"我想好了"等）→ closing
- 用户主动要建议（"你觉得"、"给个建议"等）→ advising
- 第 15 轮兜底强制 advising
- 第 5 轮起，用 LLM 判断信息是否足够给建议

### System Prompt 组装

每轮对话动态组装 system prompt，由三部分构成：

```
[BASE_ROLE 基础角色设定]
   +
[记忆上下文：用户画像 + 检索到的相关历史记忆]
   +
[当前倾向基线（如有）]
   +
[当前阶段的专属指令 STAGE_*]
```

### 对话上下文管理（短时记忆）

**策略：全量拼接 + 兜底压缩。**

基于底层模型 1M tokens 的大上下文窗口：

- **正常情况（≤ 50 轮 / 100 条消息）**：全部对话原文拼接，信息无损
- **兜底情况（> 50 轮）**：前期对话 LLM 压缩成摘要 + 保留最近 30 轮原文
- **三层降级保护**：正常压缩 → 压缩失败则简单截断 → LLM 摘要失败则返回简单文本摘要

> 说明：短时记忆（本卡片对话上下文）与长时记忆（记忆系统）是两套机制。短时记忆保证 AI"记得刚才说了什么"，长时记忆保证 AI"记得以前说过什么"。

## 2.3 即时正反馈（进展标签 + 倾向条）

**参考产品**：Reflectly / Rosebud

每次 AI 回复末尾附带结构化小卡片（progress_hint），增强单次使用价值感：

```json
{
  "assistant_message": "...",
  "progress_hint": {
    "label": "你已说清楚触发原因",
    "tendency": { "option_a": 60, "option_b": 40 },
    "next_question": "..."
  }
}
```

- **进展标签**：本轮对话进展（如"你已说清触发原因 ✓"）
- **倾向条**：当前表达倾向（如"留下 60% / 离开 40%"），仅"选择类"纠结（工作/消费）显示，进度条可视化
- **下一步引导问题**

选项名（option_a / option_b 对应的文案）通过对话内容和卡片信息智能推断（如识别到"创业"→["创业","留下"]）。倾向数据存入卡片 current_tendency 字段，作为下轮评估的基线。

## 2.4 卡片关闭与决策回顾

### 关闭方式

| 方式 | 状态 | 说明 |
|------|------|------|
| 用户做了决定 | decided | 记录决策结果、原因、残余担心 |
| 用户选择搁置 | shelved | 记录搁置原因，不再主动追问，保留所有记忆 |
| 自动检测决定 | decided | 对话中检测到强决定关键词，自然确认后关闭 |

### 关闭闭环

用户表达决定后，系统自然确认：

> "好，你决定接了。是什么让你最终下了决心？"
> "有没有什么你现在还隐隐担心的？我 3 个月后来问你回头看觉得怎么样。"

关闭时触发：
1. 记录 decision_result、decision_reason
2. 后台生成 Insight（见 2.6）
3. 触发全量记忆提取（见 2.5）
4. 启动 3 个月后的事后复盘提醒（见 2.12）

### 重新打开

已关闭卡片可重新打开（reopen），状态改回 active，延续所有记忆和对话历史——应对"我又开始纠结了"的反悔场景。

## 2.5 四种记忆的构建与检索

记忆系统是产品的技术底座，由四层记忆构成。每层记忆对应不同的产品能力。

### 四层记忆映射

| 记忆层 | 存什么 | 在产品里怎么用 |
|--------|--------|---------------|
| **核心记忆 Core** | 用户画像：身份、价值观排序、长期目标、性格（MBTI/决策风格）、人生阶段 | 决策建议的底层参数——判断哪些选项不适合用户 |
| **情景记忆 Episode** | 用户近期做的事、生活变动、关键事件 | 再次纠结时知道他最近经历了什么，结合真实变化给建议 |
| **程序记忆 Procedural** | 从已完结决策提取的事件链/因果链 + 行为模式 | ①主动触发 ②历史证据 ③预警提醒 |
| **语义记忆 Semantic** | 用户的主观认知图谱：对人/事/概念的个人看法（实体+关系） | 理解用户眼中的世界，校准认知偏差 |

### 记忆运作流程（检索）

用户每次发消息时，系统按"当前输入"语义检索相关记忆，拼入 system prompt：

```
用户输入："我又在纠结要不要换工作了"
  → 情景记忆检索：近期事件（上周提到领导换人、连续说累）
  → 核心记忆匹配：价值观排序、决策风格、人生阶段
  → 程序记忆检索：第3次纠结换工作，前2次放弃后后悔
  → 语义记忆参考：用户对"好工作""稳定"的个人定义
  → 综合生成个性化回应
```

### 记忆构建（存储）策略

**触发时机**：
- **每 10 轮对话提取一次**：第 1-10 轮直接提取；第 10-20 轮做前期摘要 + 11-20 轮原文提取；以此类推
- **卡片关闭时全量提取一次**：保证完整语境

> 记忆系统接口对同一会话的重复提交做**增量更新**（只处理新增内容），因此每 10 轮 + 关闭全量提取的组合不会产生重复存储。

### 各记忆类型当前可用性（实测）

| 记忆类型 | 构建 | 检索（语义） | 查询（列表） | 删除 | 备注 |
|---------|------|-------------|-------------|------|------|
| Episode | ✅ | ✅ | ✅ | ✅ | 完全可用，会话级粒度 |
| Semantic | ✅ | ✅ | ❌ 不支持 | — | **需富含实体关系的长对话才会提取**，短对话不生成 |
| Core | ⚠️ | ⚠️ | ⚠️ | — | 接口接受请求但实测未真正存储，待研发修复 |
| Procedural | ❌ | ❌ | — | — | **生产 API 未接入**，需研发补全 |

> **重要说明**：Episode 是会话级记忆，一次提取生成的是一条包含完整叙述的长文本（含 content、title、atomicFact 字段，atomicFact 当前为空），而非每个事实一条短记忆。

## 2.6 Insight 生成（AI 即时洞察）

**参考产品**：Rosebud

每次卡片关闭时，系统将完整对话发给 LLM，提取结构化 Insight：

```json
{
  "core_conflict": "一句话核心矛盾（≤20字）",
  "value_signals": ["价值观信号1", "价值观信号2"],
  "worry_type": "rational | emotional | mixed",
  "worry_analysis": "担忧属于理性还是情绪性的简短分析",
  "action_suggestion": "一条具体可执行的建议"
}
```

存入 cards 表的 insight 字段（JSON）。卡片详情页展示，**默认折叠只显示核心矛盾，点击展开看完整内容**（避免遮挡对话记录）。

**价值**：对话结束即可感受到价值，是核心差异化能力。

## 2.7 Insight Gallery（决策档案可视化）

**核心逻辑**：用户每次用完，不只解决了当下的纠结，还往自己的"决策档案"里存了一笔。换工具 = 历史数据清零 = 迁移成本。

### 功能形态

- Home 页"我的洞察"入口（灯泡图标）
- 顶部成就感统计条："你已经积累了 N 张决策洞察"
- 2 列网格展示所有已关闭卡片的 Insight，每张卡片显示：
  ```
  💼 换工作纠结
  核心发现：成长空间 vs 稳定
  价值观标签：从0到1的掌控感
  2026.06 · 纠结 21 天
  ```
- 点击卡片弹出详情抽屉（核心矛盾 / 价值观信号 / 担忧分析 / 行动建议）
- 可跳转回原对话

### 价值

- **即时价值**：卡片关闭时立刻看到总结
- **积累感**：看到"我已经有 10 张洞察了"，想继续积累
- **资产锁定**：Insight 积累，越用越懂自己

## 2.8 记忆可视化（历史回顾 + 个人档案）

**核心逻辑**：让用户直接看到"AI 对我的了解"，可视化记忆积累过程。

前端 Memories 页面分两个 tab：

### A. 历史回顾（Episode）

- 展示 AI 记住的所有对话内容（情景记忆）
- 按时间线展示，可回溯到任何时候的对话
- 每条记忆可删除（隐私可控）

### B. 个人档案（Core）

- 展示 AI 对用户的理解（核心记忆）
- 包含：价值观排序、决策风格、人生阶段、关注领域
- 支持手动编辑、删除
- 动态更新：随对话增加越来越精准

> ⚠️ 个人档案当前数据源为本地 users 表（Core 记忆接口待修复）。

### 价值

- **可视化记忆密度**：直观看到"AI 越来越懂我"
- **资产感知**："我积累了这么多记忆，换工具全丢了"
- **信任建立**：看到 AI 记住的细节，更信任建议

### 隐私与可控（必须跟进）

- 每条记忆显示"来源"（来自哪张卡片），可跳转
- 核心记忆支持手动编辑
- "清除所有记忆"高危入口（二次确认）
- 重要记忆标注 AI 提取标签，让用户理解为何被记录

## 2.9 长期模式识别（依赖程序记忆）

**核心逻辑**：用户积累 N 张卡片后，系统开始发现"你是怎么做决定的"。

### 解锁机制

| 积累阶段 | 解锁能力 | 输出示例 |
|---------|---------|---------|
| 冷启动期 | 基于建档的粗略画像 | 单次对话针对性追问 |
| 初识期 | 发现表层模式 | "你提到'怕后悔'的次数最多" |
| 深度期 | 发现决策模式 | "你在职业问题上理性，感情上情绪化" |
| 精通期 | 预测与预警 | "你上次也是这样，最后后悔了" |

### 四种核心识别能力

| 能力 | 记忆来源 | 输出示例 |
|------|---------|---------|
| **决策风格识别** | 程序记忆 | "你说自己理性，但 5 次纠结里 4 次听了直觉" |
| **价值观排序动态更新** | 程序/核心记忆 | "你说最在意成长，但跳槽决策里薪资是决定因素" |
| **纠结触发模式** | 程序记忆 | "你每次想换工作都是周一开完会后（3/3次）" |
| **后悔预警** | 程序记忆 | "你前 2 次拿到 offer 后因怕适应期放弃，后来都后悔了" |

### 洞察生成时机

- 不是每次对话都给（避免让用户觉得被分析）
- 积累到一定置信度再推出
- 用"提问"方式而非"断言"（"你注意到了吗？"而非"你的问题是XXX"）

> ⏳ **依赖**：此功能强依赖程序记忆（Procedural Memory）。当前生产 API 未接入，需研发补全后实现。过渡方案：关闭卡片时 LLM 提取 pattern_tags（关键词），新建纠结时匹配重叠标签 ≥ 2 的历史卡片，注入对话上下文。

## 2.10 联网搜索（按需触发）

在特定场景下，AI 自动联网搜索相关案例并总结。

### 触发时机

- 用户主动要求："帮我搜索一下 xxx"
- AI 判断需要外部信息："你说的这家公司我不了解，我去查查"
- 涉及具体重要主体（产品/公司/学校）时自动触发
- 购物决策需要产品评价等信息

### 展示方式（轻量化，不打断对话）

```
AI: 我刚看了几个类似案例，80% 的人最终选了跳槽。你可以看看这 3 条：
    📎 小红书｜互联网 3 年跳槽后悔经历
    📎 知乎｜拿到新 offer 要不要去？
    📎 OfferShow｜字节 vs 阿里选择分析
```

**限制**：每轮对话限制搜索次数，避免变成"搜索引擎客服"。

> ⏳ 待实现，依赖搜索 API 接入。

## 2.11 主动追踪与推送

**核心特征**：系统主动追问 + 用户主动，区别于通用助手的纯被动应答。

### 触发方式

- 系统主动推送（3-7 天一次，不固定避免机械感）
- 用户主动回来更新

### 推送策略（基于记忆系统）

| 推送类型 | 记忆来源 | 示例 |
|---------|---------|------|
| 普通推送 | 情景记忆 | "XX 的事最近有新想法吗？" |
| 事件关联推送 | 情景记忆 | "你上周提到领导换了，这周工作感觉怎么样？" |
| 主动触发推送 | 程序记忆 | "连续几天说累→上次这样后你就开始想换工作了" |
| 预警推送 | 程序记忆 | "你上次走到这一步放弃后后悔，这次要不要提前想想？" |

> ⏳ 待实现。频率根据纠结紧急度和用户决策风格动态调整。超过 14 天未回来则不再主动追问，下次打开时自然衔接。

## 2.12 事后复盘

**参考产品**：Reflectly / Rosebud / Mindsera

已关闭卡片 3 个月后，系统邀请用户补充事后回顾：

> "3 个月前你决定接那个 offer 了。现在回头看，你觉得这个决定怎么样？"

- 卡片详情页底部增加"事后复盘"输入框
- 复盘内容存入程序记忆（标注 source_card_id），下次相似决策时被引用
- 复盘结果可选择脱敏分享到社区（见模块三）
