# AI个性化决策助手 — 产品文档

> 科大讯飞核心研发平台 | 2026.06.10 | v0.1

---

## 一、产品定位与核心假设

### 1.1 一句话定位

**帮用户「看清自己是怎么做决定的」的AI工具。** 不替你做决策，而是通过长期追踪你的纠结过程，发现你自己都没意识到的决策模式，让你下次做得更清醒。

### 1.2 为什么不是通用助手

豆包、DeepSeek、Kimi都有记忆能力——能记住你说过的基本信息（名字、职业、偏好）。但它们的记忆是**被动摘要式的**：记住"你是产品经理"、"你喜欢简洁设计"，却不会主动追踪你两个月来对同一件事的态度变化，也不会发现你每次做决定都栽在同一个坑里。

本产品的核心差异不是"有没有记忆"，而是**记忆的用途和深度**。通用助手的记忆服务于"让每次回答更贴合你"，我们的记忆服务于"帮你在反复纠结中做出更清醒的决策"——它不只是记住你说过什么，而是在你下次犹豫时，能调动你完整的决策历史来辅助判断。

## 二、需求分析

### 2.1 目标用户

**主力人群：22-35岁城市知识工作者**

选择理由：
- Barna 2024调研：Gen-Z中39%对重要决策感到焦虑，是年长代际的2倍以上
- 86%的Gen-Z经历"选择过载焦虑"（面对过多选项时无法决策）
- 这个年龄段正处于人生关键决策密集期（职业方向、关系、城市选择、消费决策）
- 有使用AI产品的习惯

**次要人群（扩展期）：** 35-45岁中层管理者（工作决策多、压力大但不好意思跟人说）

### 2.2 用户痛点拆解

| 痛点层次 | 具体表现 | 现有解法 | 解法的问题 |
|---------|---------|---------|-----------|
| **表层：纠结时没人商量** | 想找人聊聊但怕被评判/怕泄露隐私 | 跟朋友聊、发树洞、问AI助手 | 朋友会累、树洞没回应、AI助手不追踪后续，核心功能非辅助决策 |
| **中层：做完决定不确定对不对** | 选了之后反复想"当初应该选另一个" | 自己想、写日记 | 想不清楚、日记没人帮你分析 |
| **深层：总在同一类事情上反复纠结** | 换了三次工作还是不满意、每段关系都卡在同一个点 | 心理咨询 | 贵、预约难、门槛高 |

**产品切入点：从表层痛点获客，通过中层痛点留存，用深层痛点建立壁垒。**

### 2.3 用户的纠结分类

| 类型 | 频率 | 举例 | 情绪强度 | 个性化价值 |
|------|------|------|---------|-----------|
| 人生方向类 | 低（每年1-3次） | 换不换工作、要不要考研、要不要分手 | 极高 | 极高（必须知道你是谁） |
| 工作决策类 | 中（每月数次） | 这个项目做不做、跟谁合作、汇报怎么说 | 中高 | 高（需要工作背景） |
| 关系处理类 | 中（每月数次） | 要不要道歉、怎么拒绝、要不要表白 | 高 | 高（需要关系历史） |
| 消费选择类 | 高（每周多次） | 买不买、选哪个、值不值 | 低 | 中（需要偏好和预算） |
| 日常安排类 | 极高（每天） | 今晚干嘛、周末去哪 | 极低 | 低 |

**MVP优先级：人生方向类 + 工作决策类。** 原因：情绪强度高（用户有动力来用）+ 个性化价值高（记忆系统优势明显）+ 时间跨度长（跟通用助手差异最大）。

暂不做消费选择和日常安排——情绪强度太低，用户可能懒得专门打开一个App来记录。

### 2.4 市场规模估算

**直接可参考市场：**
- 中国心理健康App市场2030年预计131亿元人民币（Grand View Research）
- 心理健康科技全球CAGR 20.2%
- BetterHelp（在线心理咨询）$10.3亿年收入、500万+用户
- Reflectly（AI日记）1000万用户

**间接参考：**
- Soul App（倾诉属性社交）3.89亿注册、1100万DAU
- 中国年轻人已接受AI聊私密话题（Guardian 2025报道）

**诚实评估：** 这不是一个已被验证的独立市场。没有"决策辅助"品类的产品做到千万级用户。市场规模取决于产品能否从"心理健康"和"效率工具"两个已有市场中切出一块。这是一个需要创造的品类，不是进入一个现有品类。

## 三、竞品调研

### 3.1 竞品全景

| 产品 | 定位 | 核心功能 | 用户量 | 融资 | 为什么不是我们的威胁 |
|------|------|---------|--------|------|---------------------|
| **Dilemmo** | 决策投票 | 列优缺点、社区投票 | 极小 | 无 | 一次性工具，无记忆 |
| **Dilemaa** | 纠结社区 | 发帖让网友帮你选 | 极小 | 无 | 纯社交，无个性化 |
| **Soul** | 社交+倾诉 | 匿名聊天、灵魂匹配 | 1100万DAU | 已上市 | 做社交不做决策 |
| **Reflectly** | AI日记 | CBT引导反思 | 1000万 | $430万 | 不追踪决策，不做模式发现 |
| **Day One** | 日记工具 | 记录+照片+时间线 | 1500万下载 | 被Automattic收购 | 纯记录无AI |
| **豆包/Kimi** | 通用AI助手 | 问答+分析+浅层记忆 | 3.45亿/千万级 | 巨头 | 记忆为回答服务，不为决策追踪服务 |
| **Wysa** | AI心理健康 | CBT练习+情绪追踪 | 500万+ | $30M | 标准化脚本，非个性化决策 |

### 3.2 竞品为什么没做好"决策辅助"

**现有产品的共同缺陷：**

1. **没有时间维度**：Dilemmo帮你列优缺点，但不知道你三个月前也纠结过同样的事
2. **没有个性化**：所有决策工具给每个人的框架都一样（SWOT分析、优缺点列表）
3. **没有模式发现**：没有产品能告诉你"你每次纠结换工作都是周一开完会之后"
4. **要么太轻、要么太重**：转盘随机选=太轻，心理咨询=太重。中间没有产品

### 3.3 真正的竞争对手是什么？

**不是上面这些产品。真正的竞争对手是：**

1. **"不做决定"**：用户选择继续纠结，不用任何工具
2. **"问朋友"**：免费、有情感温度、马上能回应
3. **"问通用AI助手"**：已经装了、不用新下载、也有基础记忆能力

所以产品必须在第一次使用时就给出超过"问朋友"和"问通用助手"的价值。核心差异不在于记忆有没有，而在于**产品围绕决策场景做了专门的结构化设计**——追问框架、纠结卡片、主动追踪、模式发现，这些是通用助手不会主动替你做的。

## 四、产品核心流程

### 4.1 用户旅程

```
第一次使用（Day 0）
├─ 选择纠结标签：用户选择自己常纠结的领域（对应5类纠结类型）
├─ 个性化建档：做几道快速测试题判断决策风格 + 选择MBTI/兴趣爱好标签
├─ 说出第一个纠结 → 系统追问结构化信息 → 建立"纠结卡片"
├─ 系统帮用户理清当前状态，并基于建档信息给出初步参考（标注"初步判断，了解你越多越准"）
└─ 价值感知：「第一次用就感觉它在试着理解我，而且给的方向还挺靠谱」

积累期（Day 1-14）
├─ 系统偶尔推送："XX的事有新想法吗？"
├─ 用户回来更新（或新增其他纠结）
├─ 系统开始建立用户画像（核心记忆）
└─ 价值感知：「它还记得我上次说的，不用重新解释背景」

洞察期（Day 14+）
├─ 系统开始发现模式（程序记忆）
│  ├─ "你注意到没有，你的重点在变化"
│  ├─ "你每次说想辞职都是周一"
│  └─ "你三个月前也想过换工作，当时放弃是因为XX"
├─ 用户感受到"它比我自己更了解我"
└─ 价值感知：「这个洞察我自己真的没注意到」← 留存关键时刻

决策后（Day X）
├─ 用户做了决定 → 系统问"为什么选这个？"
├─ 记录决策原因 → 未来可以回顾
└─ 价值感知：「之后我又纠结时，它能帮我跟过去对比」
```

### 4.2 核心交互模式

**产品结构：卡片列表 + 卡片内对话 + 全局入口。**

**主页 = 纠结卡片列表**（类似备忘录/Notion数据库视图）
- 进行中的纠结（顶部，按最近更新排序）
- 已解决的（底部，可回顾）
- 系统偶尔在卡片上贴一个"新发现"标签
- 底部常驻浮动按钮：「+ 新纠结」

**点进单张卡片 = 该纠结的专属对话空间**
- 顶部：纠结主题 + 核心矛盾 + 当前状态（进行中/已决策/搁置）
- 中部：时间线式对话记录（每次聊的内容按时间展示）
- 底部：语音/文字输入框（在这里跟系统聊这个纠结）
- 侧栏/底部Tab：系统洞察（发现的模式，用户也可以做出编辑修改）

**输入入口总结：**
- 「+ 新纠结」按钮 → 打开新卡片，语音或文字说出纠结，系统追问结构化
- 点进已有卡片 → 在卡片内继续对话、更新进展
- 系统主动推送通知 → 点进去直接到对应卡片的对话

**交互特征：**
- 对话是围绕单个纠结的结构化追问，不是开放式闲聊
- 主动推送低频（几天一次），内容是追踪类问题（"XX的事有新想法吗"）或洞察类（"发现一个规律"）

### 4.3 跟豆包的本质区别

| 维度 | 通用AI助手（豆包/Kimi） | 本产品 |
|------|----------|--------|
| 交互起点 | 用户主动提问 | 系统主动追问+用户主动 |
| 记忆深度 | 被动摘要（记住基本信息） | 被动+主动追踪（同一纠结跨月份演变+决策模式积累） |
| 记忆用途 | 让下次回答更贴合你 | 基于完整决策历史和个性化记忆给出建议 |
| 输出 | 通用的分析和建议 | 结合你的价值观、历史、行为模式的决策参考 |
| 价值来源 | 单次回答的信息质量 | 记忆/决策积累带来的个性化精度 |
| 社区 | 无 | 看"跟你有一样纠结的人最后怎么选的" |
| 竞争壁垒 | 模型能力（可被追赶） | 用户决策数据积累+社区经验库（均不可迁移） |

## 五、记忆系统架构

### 5.1 四层记忆与产品功能的映射

| 记忆层 | 存什么 | 在产品里怎么用 | 举例 |
|--------|--------|---------------|------|
| **核心记忆** | 用户画像：身份背景、价值观排序、长期目标、性格特征（MBTI/决策风格）、人生阶段 | 作为决策建议的底层参数——判断哪些选项根本不适合用户、理解纠结背后的深层原因 | 用户价值观排序"成长>稳定>收入"→ 换工作时系统知道"钱少但能学东西"对他是加分项 |
| **情景记忆** | 用户近期做的事、生活变动、发生的关键事件（从对话中提取并结构化存储） | 当用户再次纠结时，系统知道他最近经历了什么，能结合真实变化给建议而非凭空分析 | 用户上周提到"领导换了人"→ 这周纠结要不要走时，系统能关联到这个变动："上周领导刚换，这是你这次想走的触发原因吗？" |
| **程序记忆** | 从已完结决策中提取的事件链/因果链 + 日常对话中积累的行为模式 | ①主动触发：检测到当前状态匹配已知模式起点时，系统主动发起对话（如"连续情绪低→离职念头"链被激活）；②历史证据：纠结时调出"你上次类似情况选了什么、结果满不满意"作为决策参考；③预警提醒：发现用户正走向曾经后悔的路径时提前提示卡点 | "你前2次都在拿到offer后因为怕适应期放弃，后来都后悔了——这次要不要提前想想怎么应对这个阶段？" |
| **语义记忆** | 用户的主观认知图谱：对人/事/概念的个人看法（实体+关系+描述），如"我认为好的生活方式是XX"、"我觉得我领导是个XX样的人"、"远程工作对我意味着XX" | 让系统理解用户眼中的世界，决策建议时既尊重用户认知又结合客观信息——当用户认知可能存在偏差时，系统能指出盲区而非一味顺从 | 用户认为"现在的领导不给空间"→ 系统结合客观事实追问"是所有事都不给，还是某类事？"帮用户校准认知后再做判断 |

## 六、功能模块拆解

### 6.1 模块总览

| 模块 | 优先级 | 说明 |
|------|--------|------|
| 纠结创建与结构化 | P0 | 用户说一段话，系统提炼成结构化的"纠结卡片" |
| 追踪与更新 | P0 | 定期追问、记录演变、维护时间线 |
| 洞察生成 | P0 | 基于记忆系统发现用户的决策模式 |
| 对话引导 | P1 | 结构化追问帮用户理清思路（不是开放聊天） |
| 决策回顾 | P1 | 做了决定后记录原因，未来可对比 |
| 社区（匿名脱敏分享） | P2 | 看别人类似的纠结和结果 |
| 决策报告 | P2 | 月度/季度个人决策风格报告 |

### 6.2 P0模块详细设计

#### 模块A：纠结创建与结构化

**输入**：用户一段自由文本/语音（"我在纠结要不要离开现在的公司"）

**系统处理**：
1. 提取主题："换工作"
2. 判断类型：人生方向类（也可以在纠结卡片创建时候就直接让用户选）
3. 追问（不超过3个问题）：
   - "具体纠结的是什么？是钱、发展空间、还是人际关系？"
   - "现在的公司主要让你不满的是什么？"
   - "如果换了，你最担心什么？"

**输出**：一张纠结卡片
```
┌─────────────────────────────┐
│ 🔄 要不要换工作               │
│                              │
│ 核心矛盾：成长空间 vs 稳定    │
│ 不满点：工作内容重复          │
│ 担心：重新证明自己            │
│ 创建时间：2026.06.10         │
│ 状态：进行中                  │
└─────────────────────────────┘
```

**记忆写入**：
- 情景记忆：提取本次对话中的关键事件和生活变动（如"对现在工作不满"、"工作内容重复"）
- 核心记忆更新：工作阶段、价值观排序线索（"成长空间"被放在第一位提到）
- 语义记忆：用户对"稳定"的个人定义（如果对话中有体现）
- 程序记忆：如有

#### 模块B：追踪与更新

**触发方式**：
- 系统主动推送（3-7天一次，不固定避免机械感）
- 用户主动回来说

**推送策略**（基于记忆系统）：
- 普通推送（情景记忆驱动）："XX的事最近有新想法吗？"
- 事件关联推送（情景记忆驱动）："你上周提到领导换了，这周工作感觉怎么样？"
- 主动触发推送（程序记忆驱动）：检测到当前状态匹配已知模式起点，如"连续几天说累→上次这样后你就开始想换工作了"
- 预警推送（程序记忆驱动）："你上次走到这一步的时候放弃了然后后悔，这次要不要提前想想？"

**更新后处理**：
- 情景记忆更新：提取新事件/变动存入结构化记录
- 检查核心矛盾是否变化（如果变了，标注出来）
- 程序记忆检查：是否触发已有事件链模式、是否形成新的因果链
- 语义记忆检查：用户对关键概念的认知是否有变化（如"稳定"的定义变了）

#### 模块C：洞察生成

**洞察类型**：

| 类型 | 触发条件 | 记忆来源 | 输出示例 |
|------|---------|---------|---------|
| 事件关联 | 用户近期发生的事件与纠结出现时间吻合 | 情景记忆 | "上周领导换了人，这周你就开始纠结要不要走——这两件事有关系吗？" |
| 历史证据 | 相似的纠结之前出现过且有完整结果 | 程序记忆 | "你半年前也想过换，当时选了留下，后来你说还行。这次情况一样吗？" |
| 预警提醒 | 用户正走向曾经后悔的决策路径 | 程序记忆 | "你前两次都在拿到offer后因为怕适应期放弃，后来都后悔了" |
| 认知校准 | 用户的表述可能存在以偏概全或情绪化判断 | 语义记忆 | "你说领导不给空间——是所有事都不给，还是特定类型的事？" |
| 价值观冲突 | 用户的决策倾向跟自己声称的核心价值观矛盾 | 核心记忆 | "你说最在意成长，但这次三个选项里你考虑最多的还是稳定" |

**洞察的生成时机**：
- 不是每次对话都给（会让用户觉得在被分析）
- 积累到一定置信度再推出
- 用"提问"的方式而非"断言"（"你注意到了吗？" 而非 "你的问题是XXX"）

## 七、社区模块

### 7.1 社区定位

**不是社交平台，是"经验库"。** 核心价值：看看跟你类似的人最后怎么做的决定。

### 7.2 内容形态

用户选择分享时，系统自动生成"脱敏版纠结档案"：

```
┌─────────────────────────────────────────┐
│ 纠结类型：换工作                          │
│ 背景：互联网3年，觉得没成长空间            │
│ 核心矛盾：成长 vs 稳定                    │
│ 纠结时长：2个月                           │
│ 最终决策：留下，但换了团队                  │
│ 决策原因：发现问题不是公司，是这个组        │
│ 事后回顾（3个月后）：换组后确实好多了       │
└─────────────────────────────────────────┘
```

### 7.3 社区功能（MVP）

**做**：
- 匿名分享（用户选择性分享，系统自动脱敏）
- 按类型浏览（换工作/考研/关系/消费）
- 收藏到自己的参考库
- "我也是"标记（轻量互动）

**不做（V1）**：
- 1对1匹配聊天（算法复杂，体验不好就是灾难）
- 实时讨论（会变成聊天室）

### 7.4 社区 × 记忆系统

系统基于你的核心记忆（价值观、人生阶段、决策风格），推荐"跟你相似的人"的案例。不是按热度推，是按相关度推：
- 你的纠结是"换工作怕不稳定"→ 推那些"最后换了发现也OK"的案例和"没换也过得不错"的案例（两面都给）
- 你的价值观排序是"成长>稳定"→ 优先推同样价值观的人的经历
- 你的决策风格是"回避型"→ 推那些同为回避型但最终迈出一步的人的故事

### 7.5 审核策略

**原则：结构化内容比自由文本好审核。**

- 分享的内容是结构化卡片（不是自由输入），大部分字段是选择题或短文本
- AI预审核 + 人工抽检
- 初期邀请制（不是所有人都能分享，需要积累一定记录量才能解锁）
- 举报机制 + 快速下架

**成本控制**：因为内容是结构化的（不是长文/图片/视频），审核量远低于传统UGC社区。

## 8冷启动策略（Day 1问题）

**问题：第一次用，系统没有深度记忆积累，跟通用助手的体验差异不明显。**

解法：
1. **Day 0建档流程**（对应4.1用户旅程）：
   - 选择常纠结的领域标签（对应5类纠结类型）
   - 做几道决策风格测试题（快速建立核心记忆中的"决策风格"维度）
   - 选择MBTI + 兴趣爱好标签
   - 这些信息立刻写入核心记忆，第一次给建议时就能用

2. **第一次就给个性化价值**：基于建档信息，在用户说出第一个纠结时就能给出有针对性的参考（标注"初步判断"），而非等14天后才有差异化体验。

3. **设置"回来"的钩子**：创建纠结后告诉用户"3天后我会问你有没有新想法"，建立预期。

## 十、商业化路径

### 10.1 模式选择

| 模式 | 优点 | 缺点 | 适合什么阶段 |
|------|------|------|-------------|
| 免费增值（基础免费，高级付费） | 获客快 | 免费用户占比高，付费转化难 | MVP验证期 |
| 订阅制 | 收入可预测 | 低频产品订阅留存差 | 验证留存后 |
| 按需付费 | 跟"纠结时才用"的行为匹配 | 收入不稳定 | 如果被验证为"镇痛药" |
| 企业版（B2B） | 客单价高 | 决策链长，需要重新定位 | 长期扩展 |

### 10.2 建议路径

**Phase 1（MVP期）**：完全免费，追踪1-3个纠结不收钱。目标是验证假设。

**Phase 2（验证后）**：
- 免费版：同时追踪1个纠结，不限记录次数
- 付费版：无限纠结 + 洞察报告 + 社区完整功能 + 历史档案回顾
- 定价参考：Reflectly约¥50-70/月，本产品建议¥30-50/月（低于心理咨询App，高于纯工具）

**Phase 3（规模化后，如果走通）**：
- 企业版："团队决策教练"（帮管理者追踪团队的决策质量）
- 数据价值：匿名化的群体决策洞察报告（"2026年，30万人的跳槽决策分析"）

### 10.3 商业化的诚实挑战

**问题：如果产品做得好，用户决策越来越清醒、纠结越来越少，他们会不需要你。**

这跟Noom的减肥逻辑一样——减完了就不需要了。Noom的解法是"16周课程制"（不是无限订阅）。

对我们来说，解法可能是：
- 接受用户会"毕业"，靠口碑+社区带来新用户
- 产品价值从"帮你解决纠结"转向"长期自我认知档案"（你不会不要自己的日记）
- 或者接受这就是一个"低频高口碑"的产品，用社区+内容做留存

## 十一、总结与下一步

### 产品核心逻辑成立的前提

1. 用户愿意记录纠结（H1）— 需MVP验证
2. 纠结频率足够支撑使用习惯（频率悖论）— 需MVP验证
3. 记忆系统能在14天内产出有价值的个性化建议（H2）— 需技术验证
4. Day 0建档+结构化卡片能让用户感知到跟通用助手的差异（Day 1即差异化）— 需产品设计验证

### 我的判断

**方向是对的。** 用个性化记忆系统解决纠结场景的决策辅助，是AI时代的真需求，且完美匹配我们的核心能力。没有竞品说明这个赛道还没人做好，但也没被验证。

**最大风险不是技术，是使用频率。** 如果用户一年只来5次，这个产品就是一个"好用但商业化困难"的工具。MVP首先要验证的是：中间地带的纠结（不是人生大事也不是鸡毛蒜皮）到底够不够多、够不够多到让用户形成使用习惯。

### 建议的下一步

1. **做一个极简MVP**（微信小程序，2-3周能上）：验证H1和频率假设
2. **找20个用户做封闭测试**：观察他们的使用频率、回访率、纠结类型分布
3. **技术评估**：四层记忆系统在这个场景下的具体实现方案、性能要求、成本
