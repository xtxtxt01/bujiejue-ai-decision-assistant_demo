# AI个性化决策助手 — 产品说明
---
## 一、产品定位

**帮用户在纠结时做出更清醒的决策的AI工具。**

它深度理解你是谁（价值观、性格、人生阶段），知道你最近经历了什么，记得你过去每一次类似的纠结是怎么做的、结果怎么样。所以它给的建议不是通用分析框架，而是基于"你这个人"的完整决策历史和真实生活变化——能指出你自己没注意到的决策模式，能在你重蹈覆辙前提醒你，也能在你的认知有盲区时帮你校准。同时，你还能看到跟你相似的人面对同样纠结最后怎么选的。

**为什么不是通用助手：**

| 维度 | 通用AI助手（豆包/Kimi） | 本产品 |
|------|----------|--------|
| 交互起点 | 用户主动提问 | 系统主动追问+用户主动 |
| 记忆深度 | 被动摘要（记住基本信息） | 被动+主动追踪（同一纠结跨月份演变+决策模式积累） |
| 记忆用途 | 让下次回答更贴合你 | 基于完整决策历史和个性化记忆给出建议 |
| 输出 | 通用的分析和建议 | 结合你的价值观、历史、行为模式的决策参考 |
| 价值来源 | 单次回答的信息质量 | 记忆/决策积累带来的个性化精度 |
| 社区 | 无 | 看"跟你有一样纠结的人最后怎么选的" |
| 竞争壁垒 | 模型能力（可被追赶） | 用户决策数据积累+社区经验库（均不可迁移） |

## 二、目标用户

**主力人群：22-35岁城市知识工作者**

选择理由：
- Barna 2024调研：Gen-Z中39%对重要决策感到焦虑，是年长代际的2倍以上
- 86%的Gen-Z经历"选择过载焦虑"（面对过多选项时无法决策）
- 这个年龄段正处于人生关键决策密集期（职业方向、关系、城市选择、消费决策）
- 有使用AI产品的习惯

**次要人群（扩展期）：** 35-45岁中层管理者（工作决策多、压力大无人诉说）

**用户痛点分层：**

| 痛点层次 | 具体表现 | 现有解法 | 为什么不够 |
|---------|---------|---------|-----------|
| 表层：纠结时找不到合适的人聊 | 想跟人说但怕被评判、怕泄密、怕对方觉得烦；或者同一件事说三遍朋友已经听腻了 | 问朋友、发树洞、问通用AI | 朋友会腻且带偏见；树洞无反馈；通用AI每次从零开始，不记得上次聊了什么 |
| 中层：决策没有可回溯的依据 | 做完选择后反复想"当初为什么选这个"，但已经想不清当时的逻辑了 | 写日记、自己复盘 | 日记没人帮你分析规律；自己复盘容易事后合理化，看不到盲区 |
| 深层：反复栽在同一类坑里却不自知 | 换了三次工作每次都因为同一个原因后悔、每段关系都卡在同一个点，但自己意识不到这是个模式 | 心理咨询 | 贵、预约难、"我就是纠结换工作，没到需要看心理医生的程度" |

**产品切入点：从表层痛点获客，通过中层痛点留存，用深层痛点建立壁垒。**

**用户的纠结分类：**

| 类型 | 频率 | 举例 | 情绪强度 | 个性化价值 |
|------|------|------|---------|-----------|
| 人生方向类 | 低（每年1-3次） | 换不换工作、要不要考研、要不要分手 | 极高 | 极高（必须知道你是谁） |
| 工作决策类 | 中（每月数次） | 这个项目做不做、跟谁合作、汇报怎么说 | 中高 | 高（需要工作背景） |
| 关系处理类 | 中（每月数次） | 要不要道歉、怎么拒绝、要不要表白 | 高 | 高（需要关系历史） |
| 消费选择类 | 高（每周多次） | 买不买、选哪个、值不值 | 低 | 中（需要偏好和预算） |
| 日常安排类 | 极高（每天） | 今晚干嘛、周末去哪 | 低 | 中 |

## 三、核心流程

### 3.1 产品结构

**纠结卡片列表 + 卡片内对话 + 全局入口。**

**主页 = 纠结卡片列表**（类似Notion数据库视图）
- 进行中的纠结（顶部，按最近更新排序）
- 已解决的（可回顾）
- 系统偶尔在卡片上贴一个"新发现"标签
- 底部常驻浮动按钮：「+ 新纠结」

**点进单张卡片 = 该纠结的专属对话空间**
- 顶部：纠结主题 + 核心矛盾 + 当前状态（进行中/已决策/搁置）
- 中部：时间线式对话记录（每次聊的内容按时间展示）
- 底部：语音/文字输入框
- 侧栏/底部Tab：系统洞察（发现的模式，用户可编辑修改）

**输入入口：**
- 「+ 新纠结」→ 打开新卡片，语音或文字说出纠结，系统追问结构化
- 点进已有卡片 → 在卡片内继续对话、更新进展
- 系统主动推送通知 → 点进去直接到对应卡片的对话

### 3.2 用户旅程

```
第一次使用（Day 0）
├─ 选择纠结标签：用户选择自己常纠结的领域（对应5类纠结类型）
├─ 个性化建档：做几道快速测试题判断决策风格 + 选择MBTI/兴趣爱好标签
├─ 说出第一个纠结 → 系统追问结构化信息 → 建立"纠结卡片"
├─ 系统帮用户理清当前状态，并基于建档信息给出初步参考（标注"初步判断，了解你越多越准"）
└─ 价值感知：「第一次用就感觉它在试着理解我，而且给的方向还挺靠谱」

积累期（Day 1-14）
├─ 系统偶尔推送："XX的事有新想法吗？"
├─ 用户回来更新（或新增其他纠结）
├─ 系统开始建立用户画像（核心记忆）
└─ 价值感知：「它还记得我上次说的，不用重新解释背景」

洞察期（Day 14+）
├─ 系统开始发现模式（程序记忆）
│  ├─ "你注意到没有，你的重点在变化"
│  ├─ "你每次说想辞职都是周一"
│  └─ "你三个月前也想过换工作，当时放弃是因为XX"
├─ 用户感受到"它比我自己更了解我"
└─ 价值感知：「这个洞察我自己真的没注意到」← 留存关键时刻

决策后（Day X）
├─ 用户做了决定 → 系统问"为什么选这个？"
├─ 记录决策原因 → 未来可以回顾
└─ 价值感知：「之后我又纠结时，它能帮我跟过去对比」
```

## 四、核心功能

### 功能一：个性化决策支持

首次使用时完成建档，之后每次纠结走完整的决策支持流程：创建纠结卡片 → 新记忆导入 → 老记忆提取 → 多轮对话 → 个性化建议 → 关闭纠结。

**0. 首次建档（Day 0）**

用户首次使用时完成快速自画像，形成初始用户画像（核心记忆）：
- 常纠结领域标签
- MBTI类型或性格倾向
- 决策风格测评（几道快速选择题，判定决策倾向）
- 可选：兴趣爱好、当前人生阶段

建档信息让系统从第一次对话起即可提供个性化回应。后续对话中系统持续补充和修正画像。

**1. 创建纠结卡片**

用户选择纠结类型后，用语音或文字描述当前纠结。系统通过不超过3个追问完成结构化：
- 澄清核心矛盾：纠结的本质是什么之间的冲突
- 追问触发点：什么事件让这个纠结浮现
- 明确担忧：最怕的后果是什么

系统据此生成纠结卡片，包含：纠结主题、核心矛盾、触发点、主要担忧、当前状态。卡片帮用户将模糊的焦虑转化为结构化的问题——很多纠结在理清之后本身就减轻了。

**2. 新记忆导入**

对话过程中，系统自动提取并存储关键信息，无需用户手动整理：
- 价值观信号：用户表述中隐含的优先级排序 → 更新价值观模型
- 近期变动：生活/工作中的新事件 → 写入情景记忆
- 主观定义：用户对抽象概念的个人理解 → 更新语义记忆

**3. 老记忆提取**

系统基于当前纠结，自动匹配和调动历史记忆，提供四类回应：
- **关联近期变化**：将近期事件与当前纠结建立因果联系，帮用户看到触发链
- **调出历史证据**：找到同类纠结的历史记录，对比当时的情境和结果
- **预警重复路径**：识别用户曾经在相似决策节点上的行为模式，提前预警
- **指出价值观矛盾**：对比用户声称的价值排序和实际选择行为之间的偏差

**4. 多轮对话**

决策支持不是单次交互，而是跨天、跨周的持续过程：
- **用户主动更新**：用户随时回来补充新进展，系统基于完整历史衔接，无需重新解释背景
- **系统主动触达**：每3-7天低频追问进展，频率根据纠结紧急度和用户决策风格动态调整
- **模式发现提醒**：当系统积累足够数据后，主动提示用户未察觉的决策模式或认知变化

**5. 给出个性化决策建议**

系统综合以下维度生成决策参考：
- **身份维度**：用户的价值观、性格特质、人生阶段
- **情境维度**：近期变动、情绪状态、外部约束
- **历史维度**：同类决策的过往选择、结果和行为模式
- **认知校准**：在尊重用户框架的前提下，指出盲区或认知偏差

输出不是"你应该选A"的标准答案，而是帮用户看清在其个人背景下各选项的真实含义和可能后果。

**6. 关闭纠结**

用户在对话中表达明确决定后，系统确认并完成闭环：
- 记录决策结果、决策原因、残余担心（写入程序记忆）
- 卡片标记为"已决策"，可随时回顾
- 启动事后回顾，回顾结果可选择脱敏分享到社区

用户也可选择"搁置"——系统记录搁置原因，不再主动追问，但保留所有记忆供后续重新打开。

### 功能二：纠结社区

**定位：决策经验库，不是社交平台。**

核心价值：让用户看到"跟我情况相似的人，面对同样的纠结，最后怎么选的、结果怎么样"。

**内容来源：**

用户纠结卡片关闭3个月后，系统邀请补充事后回顾。填写后询问是否愿意脱敏分享。脱敏规则：
- 自动去除个人身份信息（公司名、人名、具体薪资等）
- 保留决策结构（背景、核心矛盾、纠结时长、最终选择、决策转折点、事后回顾）
- 用户可预览脱敏版并编辑后再确认发布

**案例结构：**

每个社区案例包含：纠结类型、脱敏背景、核心矛盾、纠结时长、最终决策、决策原因、事后回顾（必须有结果验证才进入推荐池）。

**个性化推荐逻辑：**

匹配维度围绕"对这个决策有参考价值"的因素，而非表面相似度：
- 纠结类型与决策阶段（同类决策、同一卡点）
- 核心卡点（怕的东西一样）
- 决策风格（同类型的人应对方式更可借鉴）
- 人生阶段（约束条件相似）

不匹配行业、公司、薪资等表面信息。按相关度推荐，非按热度排序。

**使用方式：**
- 用户主动浏览：按纠结类型分类展示，可收藏到个人参考库
- 系统主动推荐：在UC-01决策对话中，当用户进入僵局时，系统将高匹配案例作为对话素材引入，推进决策而非独立展示
- 轻量互动："我也是"共鸣标记

## 五、目标场景 Use Case

### UC-01：个性化决策支持——反复纠结换工作

| 字段 | 说明 |
|------|------|
| 参与者 | 用户（主）、AI决策助手（系统）|
| 触发条件 | 用户创建新的纠结卡片或重新打开已有纠结 |
| 前置条件 | 用户已完成Day 0建档，系统已有基础用户画像 |
| 后置条件（成功） | 用户获得基于个人历史和特质的决策参考，记忆系统完成本次更新 |
| 后置条件（最小） | 纠结卡片已创建，核心矛盾已结构化，即使用户中途离开也有价值 |

**用户画像：** 28岁产品经理，工作3年。建档信息：价值观"成长>稳定>收入"，决策风格偏回避型，MBTI为INFP，常纠结领域为"职业发展"。

---

**主流程（Main Flow）：**

**1. 创建纠结卡片**

选完纠结分类后，用户输入"我又在纠结要不要换工作了"。系统识别到纠结主题为"职业发展"，发起澄清追问几个问题例如：

> "换工作这个念头是最近才有的，还是一直在想？主要让你不舒服的是什么——工作内容、人、还是看不到空间？"

用户回答后，系统结构化生成纠结卡片：

```
┌─────────────────────────────────────┐
│ 要不要换工作                          │
│ 核心矛盾：成长空间 vs 重新证明自己    │
│ 触发点：新领导来了，风格不适应        │
│ 不满点：工作内容重复，没有成长感      │
│ 状态：进行中                          │
└─────────────────────────────────────┘
```

**2. 新记忆导入**

对话过程中系统自动提取关键信息并更新记忆：
- "成长空间"被排在第一位提到 → 更新价值观排序
- "新领导风格不适应"、"工作内容重复" → 记录为近期事件
- "稳定对我来说不是钱的问题，是不想重新证明自己" → 更新用户对"稳定"的主观定义

**3. 老记忆提取**

系统匹配历史记忆，发现这是第3次纠结换工作，调出相关证据：

> "你半年前也想过换，当时选了留下，后来你说还行但不够好。这次情况一样吗？"
>
> "你前两次都走到拿offer阶段后因为怕适应期放弃了，后来都说后悔。这次如果认真考虑，要不要提前想想怎么应对那个阶段？"
>
> "上周你提到新领导来了风格变化大，这周就在想走——是新领导让你不舒服，还是本来就想走、领导换了只是个触发？"

**4. 多轮对话（跨轮跨天持续）**

| 时间 | 事件 | 系统响应 |
|------|------|----------|
| Day 3 | 用户："我跟朋友聊了下，他说我这是逃避" | "你觉得他说得对吗？你上次留下的时候也有人说你逃避——那次你后来的感受是什么？" |
| Day 8 | 系统主动触达（低频，3-7天一次） | "换工作的事有新想法吗？" |
| Day 12 | 用户："我拿到一个offer了" | 系统识别历史预警——前两次都卡在这一步，进入Step 5 |

**5. 给出个性化决策建议**

> "你已经是第三次走到这一步了。前两次拿到offer后因为怕适应期放弃，后来都后悔。你说最在意成长，但每次到选择的时候考虑最多的是稳定——这不矛盾，只是说明你需要把'适应期怎么过'这个问题提前解决，而不是到时候再纠结。要不要聊聊这个offer的适应期你具体怕什么？"

**6. 关闭纠结（决策完成）**

在多轮对话过程中，用户表达了明确决定（如"我决定接这个offer了"），系统在对话中自然确认：

> "好，你决定接了。是什么让你最终下了决心？"

用户回答后，系统继续问：

> "有没有什么你现在还隐隐担心的？我3个月后来问你回头看觉得怎么样。"

用户回答完毕，系统自动将卡片标记为"已决策"并完成：
- 记录决策结果、决策原因、残余担心（写入程序记忆，作为未来类似纠结的参考）
- 卡片可随时回顾
- 启动3个月后的事后回顾提醒（回顾结果可选择脱敏分享到社区，见UC-02）

---

**备选流程（Alternative Flows）：**

| 编号 | 分支点 | 场景 | 系统行为 |
|------|--------|------|----------|
| 1a | Step 1 | 首次纠结（无历史记忆） | 跳过Step 3老记忆提取，专注澄清和新记忆建立 |
| 4a | Step 4 | 用户超过14天未回来 | 系统不再主动追问，下次用户打开时自然衔接 |
| 5a | Step 5 | 用户当前信息不足以给建议 | 系统说明"目前我能帮你做的是理清纠结点，等你有更多进展再一起看" |
| 6a | Step 6 | 用户说"我不想换了，算了"（放弃而非决策） | 系统确认后关闭卡片，同样记录放弃原因，标记为"搁置" |
| 6b | Step 6 | 用户关闭后又反悔（"我又开始纠结了"） | 重新打开卡片，延续之前所有记忆和对话历史 |

**异常流程（Exception Flows）：**

| 编号 | 场景 | 系统行为 |
|------|------|----------|
| E1 | 新用户未完成建档直接创建纠结 | 允许创建，但对话中额外追问基础信息，补充核心记忆 |
| E2 | 用户情绪明显负面或表达极端倾向 | 回应以关心为主，不推进决策分析，必要时建议寻求专业支持 |

### UC-02：纠结社区——看相似的人怎么选的

| 字段 | 说明 |
|------|------|
| 参与者 | 用户（主）、AI决策助手（系统）、已决策用户（内容贡献者） |
| 触发条件 | 1）用户主动浏览社区；2）UC-01对话中系统判断用户处于决策僵局，主动推荐 |
| 前置条件 | 用户已完成建档；社区中已有同类型、已关闭且有事后回顾的纠结案例 |
| 后置条件（成功） | 用户获得"相似的人的真实决策经历+结果验证"作为参考，降低决策不确定性 |

**用户画像：** 同UC-01用户。当前状态：拿到offer后第3天，连续问了两轮"要不要接"但无法推进，系统判断用户进入决策僵局。

---

**主流程（Main Flow）：**

**1. 触发推荐（系统判断时机）**

系统在UC-01对话中识别到僵局信号：
- 用户连续2轮表达犹豫但无新信息输入
- 历史模式显示用户在这个环节容易卡住
- 个性化建议已给出但用户仍未行动

系统在对话中自然引入：
> "你现在的纠结点主要是怕适应期。社区里有几个跟你情况很像的人——也是工作2-3年、纠结换工作、拿到offer后犹豫的。他们后来的选择和结果我可以给你看看，要不要参考一下？"

**2. 个性化匹配（基于决策相关维度）**

匹配不是简单的标签对比，而是围绕"对这个决策真正有参考价值"的维度：

| 匹配维度 | 为什么匹配这个 | 本用户 | 命中案例 |
|----------|---------------|--------|----------|
| 纠结类型+阶段 | 同类决策才有参考性 | 换工作，卡在接offer | 换工作，曾卡在接offer |
| 核心卡点 | 怕的东西一样才有共鸣 | 怕适应期 | 怕适应期 |
| 决策风格 | 同类型的人应对方式更可借鉴 | 回避型 | 回避型 |
| 人生阶段 | 约束条件相似 | 28岁未婚，无房贷 | 27岁未婚，无房贷 |

不匹配的维度：行业、具体公司、薪资——这些是表面信息，不影响"纠结的本质"。

**3. 展示案例（聚焦决策过程和结果验证）**

```
┌─────────────────────────────────────────────────────┐
│ 跟你相似的案例 #1                                     │
│                                                       │
│ 背景：工作2.5年，团队重组后觉得没空间，拿到offer犹豫  │
│ 卡点：跟你一样——怕适应期，怕"重新证明自己"           │
│ 纠结了多久：拿到offer后犹豫了10天                     │
│                                                       │
│ 最终选择：接了offer                                   │
│ 决策转折点：想通了"适应期不舒服"和"一直待着不成长"    │
│            哪个更让自己后悔                            │
│                                                       │
│ 事后回顾（3个月后）：                                 │
│ "前2周确实焦虑，但第3周开始就顺了。                   │
│  回头看，之前犹豫的那10天比适应期本身更难受。"        │
└─────────────────────────────────────────────────────┘
```

关键设计：案例必须包含"事后回顾"——没有结果验证的案例不进入推荐池。

**4. 系统将案例整合回决策对话**

看完案例后，系统不是让用户自己消化，而是主动关联回用户的具体情况：

> "这个案例里他说'犹豫的那10天比适应期本身更难受'——你现在也在这个阶段。你觉得你怕的适应期，具体是哪一段？是前几天不熟悉环境，还是更长期的证明自己的压力？"

案例作为对话素材被系统调用，推进UC-01的决策对话，而不是看完就结束。

**内容来源：用户如何成为贡献者**

纠结卡片被标记为"已决策"3个月后，系统邀请用户补充事后回顾：
> "3个月前你决定接那个offer了。现在回头看，你觉得这个决定怎么样？"

用户填写后，系统询问是否愿意脱敏分享到社区。脱敏规则：
- 自动去除公司名、人名、具体薪资
- 保留决策结构（矛盾、卡点、转折点、结果）
- 用户可预览脱敏版并编辑后再确认发布

**备选流程（Alternative Flows）：**

| 编号 | 分支点 | 场景 | 系统行为 |
|------|--------|------|----------|
| 1a | Step 1 | 用户主动进入社区浏览（非僵局触发） | 按纠结类型分类展示，用户自行浏览，不强制关联回对话 |
| 2a | Step 2 | 高相似案例不足3个 | 放宽匹配（如不限决策风格），标注"部分相似" |
| 4a | Step 4 | 用户看完案例说"他的情况跟我不一样" | 系统追问差异点，调整匹配维度重新推荐 |

**异常流程（Exception Flows）：**

| 编号 | 场景 | 系统行为 |
|------|------|----------|
| E1 | 冷启动期无同类案例 | 不推荐社区，继续UC-01个性化对话 |
| E2 | 用户看到案例后情绪更焦虑（"他成功了我肯定不行"） | 系统识别负面对比心态，回应："每个人情况不同，这只是参考。回到你自己——你觉得你跟他最大的区别是什么？" |
